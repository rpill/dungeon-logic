# Dungeon Logic Campaign v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a backendless 5-level Campaign v1 pilot with persistent linear progression, mixed puzzle archetypes, Graveyard visual theming, contextual onboarding, deterministic candidate promotion, Level Select, and campaign-aware completion while preserving all existing dev/test level flows.

**Architecture:** Campaign is a separate pure-TS subsystem above the puzzle core. Static campaign content owns chapters, curation constraints, promoted snapshots, and theme selection; `CampaignService` owns normalized progress and persistence; launch routing resolves either a dev level or a campaign entry before `GameScene` starts. Board rendering consumes a campaign-agnostic `BoardVisualTheme`, so puzzle rules and solver data never depend on chapter or art.

**Tech Stack:** TypeScript 6, Phaser 4.2, Vite 8, Node/tsx sanity scripts, existing ORYX Ultimate Fantasy assets already under `public/assets/oryx`.

**Spec:** `docs/superpowers/specs/2026-09-07-campaign-v1-design.md`

## Global Constraints

- Dungeon Logic has **no custom backend**. Do not add a private HTTP API, custom database, custom account service, server-authoritative economy/gameplay, secret server credentials, or custom cron jobs.
- Keep `CampaignProgressStorage` async. This implementation ships `LocalCampaignProgressStorage`; a later Yandex Games adapter must fit the same interface without changing campaign progression or scenes.
- Do not add Yandex SDK integration in this plan.
- Do not change puzzle rules, `LevelValidator`, Puzzle Solver behavior, Human Solver behavior, Difficulty Analyzer scoring/bands, or Generator Difficulty v2 behavior.
- Generator Difficulty v2 is frozen. Campaign tooling may call its public analysis/evaluation helpers but must not tune generation policy.
- Do not move, rename, or promote `src/data/levels/level001.ts` through `level012.ts`; they remain technical authored/regression content.
- Production campaign runtime must never read `.generated`.
- Campaign v1 snapshots use Monsters and Treasure Rooms only; no Blockers or Directional Doors in promoted campaign content.
- The pilot promotes exactly five levels with the approved mixed rhythm: `monster-only`, `chest-one-room`, `monster-only`, `mixed-one-room`, `chest-one-room`.
- All five pilot levels belong to the `graveyard` chapter/theme. Do not implement Desert/Sewers/Crypt campaign levels yet, but define their static chapter/theme metadata now.
- Planned Campaign v1 has 30 curation slots. Level Select displays **only promoted entries**; slots 6–30 remain invisible during the pilot.
- Campaign slots are stable, positive, and contiguous among promoted entries. Slot N uses id `campaign-NNN`.
- Campaign is completion-only: no stars, timer grading, move grading, score, chapter rewards, world map, chapter-select screen, or expert main-campaign levels.
- A visual theme may change floor/wall/background/entity/decorative art only. It must not change clue semantics, topology, input behavior, puzzle state semantics, save state, or solver/validator results.
- `LevelDefinition` stays campaign-agnostic. Do not add `chapterId` or `themeId` to puzzle definitions.
- `BoardView`/`CellView` may depend on `BoardVisualTheme` but must not import campaign manifests, campaign progress, chapter ids, or promotion metadata.
- Existing valid `?level=<n>` technical playtest and dev-only valid `?seed=<uint32>&candidate=<id>` generated playtest must continue to work and must not load or mutate campaign progress.
- Save corruption must not crash the game. Save failure must not undo in-memory progress or suppress a solved-level result.
- Promotion validates every gate before persistent writes and produces deterministic source with no timestamps, random formatting, or machine-specific paths.
- User-facing tests assert behavior, not pixel coordinates or final art styling.
- In the ZIP-overlay workflow, do not ask the user to commit intermediate micro-steps. Internal isolated-worktree commits are allowed; user-facing commit/verification happens after the final GREEN package.

    id,
    width: 2,
    height: 2,
    rowClues: [0, 0],
    columnClues: [0, 0],
    monsters: [],
    chests: [],
    blockers: [],

const manifest: readonly CampaignLevelEntry[] = [1, 2, 3].map((slot) => ({
  slot,
  id: `campaign-${String(slot).padStart(3, '0')}`,
  level: fixtureLevel(`campaign-${String(slot).padStart(3, '0')}`),
  chapterId: 'graveyard',
  onboarding: slot === 1

assert(getCampaignLevelState(manifest[0], fresh) === 'current', 'Slot 1 is current.');
assert(getCampaignLevelState(manifest[1], fresh) === 'locked', 'Slot 2 is locked.');
assert(shouldShowCampaignOnboarding(manifest[0], fresh), 'Slot 1 onboarding shows before completion.');

const afterOne = completeCampaignProgress(fresh, 'campaign-001', manifest);
assert(afterOne.highestUnlockedSlot === 2, 'Completing slot 1 unlocks slot 2.');
assert(afterOne.completedLevelIds.join(',') === 'campaign-001', 'Completion ids are canonical.');
assert(!shouldShowCampaignOnboarding(manifest[0], afterOne), 'Replay hides completed onboarding.');
assert(shouldShowCampaignOnboarding(manifest[1], afterOne), 'Treasure Room onboarding appears on slot 2.');

const repeated = completeCampaignProgress(afterOne, 'campaign-001', manifest);
assert(repeated.highestUnlockedSlot === 2, 'Replay cannot advance unlock.');
assert(repeated.completedLevelIds.length === 1, 'Replay completion is idempotent.');

const normalized = normalizeCampaignProgress({
  schemaVersion: 1,
  highestUnlockedSlot: 99,
  completedLevelIds: ['campaign-003', 'campaign-001', 'campaign-001', 'campaign-999'],
  lastPlayedLevelId: 'campaign-003',
}, manifest);
assert(normalized.completedLevelIds.join(',') === 'campaign-001', 'Only contiguous known completion prefix survives.');
assert(normalized.highestUnlockedSlot === 2, 'Stored unlock number is recomputed.');
assert(normalized.lastPlayedLevelId === null, 'Locked last-played id is cleared.');

const started = setLastPlayedCampaignLevel(afterOne, 'campaign-002', manifest);
assert(started.lastPlayedLevelId === 'campaign-002', 'Playable level becomes last played.');
assert(getCampaignContinueEntry(started, manifest)?.id === 'campaign-002', 'Continue prefers valid last played.');

let duplicateRejected = false;
try {

assert(duplicateRejected, 'Duplicate campaign slots are rejected.');

function range(start: number, end: number): readonly number[] {

}

export const campaignChapters = [

  { id: 'desert-ruins', title: 'Desert Ruins', themeId: 'desert-ruins', slots: range(7, 13) },

export function getCampaignChapter(id: CampaignChapterId): CampaignChapterDefinition {
  const chapter = campaignChapters.find((entry) => entry.id === id);

  return chapter;

  const chapter = campaignChapters.find((entry) => entry.slots.includes(slot));
